# Eigen

Eigen is a self-hostable SvelteKit memory infrastructure app with **Better Auth**, **Drizzle ORM**, **pgvector**, and **Apache AGE**.

This repository is a **fully self-contained Docker Compose stack** — no external services, no third-party databases, no cloud dependencies. Everything runs in containers.

## Architecture

| Service | Container | Role |
|---------|-----------|------|
| `app` | `eigen-app` | SvelteKit app with `@sveltejs/adapter-node` on port 3000 |
| `db` | `eigen-db` | PostgreSQL 16 with pgvector + Apache AGE extensions on port 5432 |
Both are defined in [`docker-compose.yaml`](./docker-compose.yaml) and build from source in this repo.

## Prerequisites

- Docker with `docker compose` plugin (Docker Desktop, OrbStack, or a Linux host)
- Git
- `openssl` (for `./install.sh`)

No Node.js or npm is required on the host for production deployment.

## Quick Start (Production Stack)

**Bare VPS:** full runbook at [`docs/operations/vps-install.md`](./docs/operations/vps-install.md).

```sh
git clone https://github.com/hikaru90/eigen.git && cd eigen
./install.sh --non-interactive --origin https://your.domain --billing platform
# Edit .env — add LLM gateway credentials (and PayPal if using platform credits)
docker compose up -d --build
```

The app entrypoint ([`entrypoint.sh`](./entrypoint.sh)) applies database migrations and RLS on every container start — no manual `npm install` on the host.

The app is available at your `ORIGIN` (or `http://<your-host>:3000` if you skip TLS).

## Required Environment Variables

`./install.sh` generates most secrets automatically. You must still configure LLM credentials (and PayPal for platform credits).

### Non-negotiable (generated by install.sh or set manually)

| Variable | Purpose | How to set |
|----------|---------|------------|
| `BETTER_AUTH_SECRET` | Session encryption | `install.sh` or `openssl rand -base64 32` |
| `TENANT_MASTER_KEY` | Tenant envelope encryption | `install.sh` or strong random secret |
| `AGE_GRAPH_NAME` | Apache AGE graph name | `eigen_graph` (default) |
| `ORIGIN` | Public URL for auth and OAuth | `./install.sh --origin …` |

### LLM — at least one billing path

**Platform credits** (Eigen wallet, default user billing):

| Variable | Purpose |
|----------|---------|
| `SERVICE_API_KEY_EUROUTER` | EUrouter service key |
| `LLM_BASE_URL` | EUrouter API origin (e.g. `https://api.eurouter.ai/v1`) |
| `LLM_RULE_CHAT`, `LLM_RULE_EMBEDDING` | EUrouter routing rule UUIDs |
| `PAYPAL_API_BASE`, `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET` | PayPal REST app (wallet top-ups) |

**BYOK only** (users supply keys in Settings → LLM → BYOK):

| Variable | Purpose |
|----------|---------|
| `LLM_BASE_URL`, `LLM_API_KEY` | EUrouter env fallback |
| `LLM_RULE_CHAT`, `LLM_RULE_EMBEDDING` | EUrouter rule UUIDs |

Set variables in `.env` at the project root or in your platform dashboard. Compose passes DB URLs, `AGE_GRAPH_NAME`, `ORIGIN`, `HOST`, and `PORT` to the app container.

## Deploying to Coolify

1. **Connect the repository** in Coolify.
2. **Select "Docker Compose" as the Build Pack.** Coolify detects `docker-compose.yaml` automatically.
3. **Add environment variables** in the Coolify dashboard (see [Required Environment Variables](#required-environment-variables)). Set `POSTHOG_SOURCEMAPS_REQUIRED=0` unless you provide a PostHog personal API key (`phx_…`) at build time.
4. **Deploy.** Coolify builds and starts both containers.
5. Migrations and RLS run automatically via the app entrypoint on start.

### Why Docker Compose and not the Dockerfile build pack?

The app requires PostgreSQL with pgvector + AGE (graph data lives in the same database). The standalone `Dockerfile` only builds the app image. **Docker Compose is the correct build pack for this project.**

### Port Mapping

By default `docker-compose.yaml` maps:
- `3000:3000` — app
- `5432:5432` — Postgres

Change port mappings in `docker-compose.yaml` if they conflict with existing services on your host.

## Troubleshooting (migrations)

If the entrypoint failed to migrate, run manually inside the app container:

```sh
docker compose exec app node scripts/migrate.mjs
docker compose exec app node scripts/apply-rls.mjs
```

## Production Hardening

Before going live:

1. **Use `./install.sh`** or rotate all default secrets (`BETTER_AUTH_SECRET`, `POSTGRES_PASSWORD`, `TENANT_MASTER_KEY`).
2. **Set `ORIGIN`** to your actual public URL (HTTPS when using a reverse proxy).
3. **Restrict Postgres port** — remove `ports: ['5432:5432']` from `docker-compose.yaml` so the database is only reachable on the internal Docker network.
4. **Use a real LLM gateway** — the app requires an OpenAI-compatible `/api/v1/chat/completions` and `/api/v1/embeddings` endpoint.
5. **TLS** — put Caddy or nginx in front of port 3000; see [`docs/operations/vps-install.md`](./docs/operations/vps-install.md).
6. **Lock Node.js version** — the Dockerfile uses `node:22-bookworm-slim`. Pin a specific patch if needed.

## Development (Local, Non-Containerized)

```sh
npm install
cp .env.example .env
npm run db:up      # start Postgres container only
npm run dev        # run the SvelteKit dev server on :5173
```

## Database Lifecycle Commands

| Command | What it does |
|---------|-------------|
| `npm run db:up` | Start `db` container only |
| `npm run db:import-graph-export` | Import a graph export JSON into AGE (`--from-export <path>`) |
| `npm run db:down` | Stop all compose services |
| `npm run db:reset` | Stop services and delete DB volume (destructive) |
| `npm run db:push` | Apply Drizzle schema (interactive) |
| `npm run db:push:force` | Apply Drizzle schema (non-interactive) |
| `npm run db:rls` | Apply Row-Level Security policies |
| `npm run db:init` | `db:push:force` + `db:rls` |
| `npm run stack:up` | Build and start all containers (app + db) |
| `npm run stack:down` | Stop all containers |
