# Domain: UI surfaces

**Canonical rule:** Product UI lives under [`src/routes/`](../../src/routes/). Mutations from the browser use **native `fetch`** to explicit `+server.ts` routes (per project guardrails), not ad-hoc server functions from client bundles.

**Design system (ei redesign, 2026-10):** [`docs/planning/ei-redesign.md`](../planning/ei-redesign.md) is the implementation contract; the spec is `~/+Code/ei/DESIGN.md`. Tokens live in [`src/routes/layout.css`](../../src/routes/layout.css) and are mapped onto the shadcn variables (`--background`=`--paper`, `--card`=`--raised`, `--muted`=`--paper-2`, `--muted-foreground`=`--ink-3`, `--border`=`--line`, `--destructive`=`--warn`, `--ring`=`--signal`), so every page inherits paper/ink without per-page colour classes. Pages must not reintroduce raw palette colours (`bg-white`, `text-green-500`, …); coloured text uses `--clay` / `--signal` / `--warn`, which are the only text-grade colours on light paper.

## CompetingSystems

- **Demo routes vs product:** [`src/routes/demo/`](../../src/routes/demo/) contains Paraglide and Playwright demos — not the memory product surface. Prefer [`capture`](../../src/routes/capture/), [`mesh`](../../src/routes/mesh/), [`chat`](../../src/routes/chat/), [`thought`](../../src/routes/thought/), [`activity`](../../src/routes/activity/), [`settings`](../../src/routes/settings/) for product behavior.
- **New chrome vs legacy secondary nav:** the product chrome is [`src/lib/components/chrome/`](../../src/lib/components/chrome/) (see *Chrome*). [`memory-surface-nav.svelte`](../../src/lib/components/memory-surface-nav.svelte) is the **legacy** Desk/Graph/Embeddings/Tasks/Projects/Notes strip; it is still mounted only by the unlinked legacy pages ([`memory/+layout.svelte`](../../src/routes/memory/+layout.svelte), [`desk/+page.svelte`](../../src/routes/desk/+page.svelte)) and must not be added to new surfaces.

## Chrome (one container, floating header + bottom nav)

[`src/routes/+layout.svelte`](../../src/routes/+layout.svelte) mounts [`chrome/app-chrome.svelte`](../../src/lib/components/chrome/app-chrome.svelte) on every product page and hides it on the auth paths (`/login`, `/signup`, `/register`, `/forgot-password`, `/reset-password` — the `authPaths` set in the layout). PWA / push / analytics / beta-agreement / capture-queue wiring stays in the layout.

- **Header:** the six-square mark ([`brand/eigen-mark.svelte`](../../src/lib/components/brand/eigen-mark.svelte)) linking to `/capture`; the whisper line ([`stores/whisper.svelte.ts`](../../src/lib/stores/whisper.svelte.ts)); **Make me better** entry + glimpse + news dot ([`chrome/make-me-better-entry.svelte`](../../src/lib/components/chrome/make-me-better-entry.svelte) → `/feedback`); the **view select** ([`chrome/view-select.svelte`](../../src/lib/components/chrome/view-select.svelte), signed-in only): a small dropdown beside the you-menu icon switching the global data view (You / agent layers / All Users — the `current-user-view` store); the **non-modal you-menu** ([`chrome/you-menu.svelte`](../../src/lib/components/chrome/you-menu.svelte)): *Look* (Light / Dark / Auto) plus links to `/settings`, `/api-keys`, `/activity` and Sign out. The pre-redesign header and its view popover were deleted; this header dropdown replaced them.
- **Bottom nav:** [`chrome/bottom-nav.svelte`](../../src/lib/components/chrome/bottom-nav.svelte) — exactly three items: **Capture** (`/capture`), **Mesh** (`/mesh`), **Ask** (`/chat`), drawn with [`brand/menu-mark.svelte`](../../src/lib/components/brand/menu-mark.svelte); active state resolved by [`chrome/nav-active.ts`](../../src/lib/components/chrome/nav-active.ts).
- **Theme (Look):** one contract shared by the you-menu and `/settings`: `localStorage['theme-preference']` ∈ `light | dark | system`, applied by toggling `.dark` on `<html>`, and broadcast as the `theme-preference-change` window event. Both controls write it and both listen for it, so they never disagree. Do not introduce a second store or a `data-theme` attribute.
- **Nothing in the new chrome links to** `/memory`, `/desk`, `/graph`, `/memory/notes`, `/memory/tasks` (decision 1 in the plan): those stay URL-reachable only.

## Route map (high level)

Each entry: **Purpose** / **Owns** (user-visible concern) / **Key server load** (if any).

- **`/`** — No page of its own: [`+page.server.ts`](../../src/routes/+page.server.ts) redirects to `/capture` when signed in, `/login` otherwise.
- **`/capture`** — Primary thought capture (the writer). Interpretation runs **up front** while typing as a **read** (`POST /api/capture/read`, debounced ~600 ms, ≥8 chars): preview only — `interpretThoughtPreview` runs, **nothing is stored** (no `queueCapture`, no thought row). The live reading shows inline type / thread controls that edit a client-side copy of the accepted reading (type chosen among the LLM's own alternatives). Pressing Capture **keeps** it in one call (`POST /api/capture/keep { raw, reading }` → `keepCaptureWithReading`): the thought row is written once, `raw_text` = the typed words verbatim, `normalized_text` = the accepted `interpretedText`, enrich scheduled — no post-submit modal. A chosen thread is then assigned via the existing `POST /api/timeline/projects/assign`. **Offline or a stale reading** → the client capture queue (`POST /api/capture/submit { raw }`, unchanged; [capture-queue.md](./capture-queue.md)). `POST /api/capture/interpret` + `/api/capture/confirm` remain for legacy / e2e callers only. **Edits** `fetch` `/api/capture/edit`. Attachments and voice input remain. **Voice** ([`voice-input-button.svelte`](../../src/lib/components/voice-input-button.svelte), logic in [`capture/segmented-stt.ts`](../../src/lib/capture/segmented-stt.ts)): records independent segments (a fresh `MediaRecorder` per segment on one stream), cut at a ≥350 ms pause once ≥3 s, forced at 10 s; each segment goes once to `POST /api/capture/transcribe-chunk` (≤2 MiB, with a segment index); partial and final text = ordered join of segment transcripts. A segment failing 3 attempts (or any 402) stops recording with an explicit error and clears the partial. There is no full-recording upload ([feature-segmented-stt.md](../planning/feature-segmented-stt.md)). The recent-thoughts list moved to Yarn. Load: [`capture/+page.server.ts`](../../src/routes/capture/+page.server.ts).
- **`/mesh`** — The Mesh hub (bottom nav). `/mesh` redirects to `/mesh/yarn` ([`mesh/+page.server.ts`](../../src/routes/mesh/+page.server.ts)); [`mesh/+layout.svelte`](../../src/routes/mesh/+layout.svelte) owns the floating tab group (**Yarn / Threads / Patterns**) and the in-track search.
  - **`/mesh/yarn`** — every thought on one strand, grouped by day with running-stitch separators; to-dos carry a tick ring; every row has an explicit open control (rows never open on tap) leading to `/thought/[id]`. Row component: [`components/mesh/thought-row.svelte`](../../src/lib/components/mesh/thought-row.svelte). Load: [`mesh/yarn/+page.server.ts`](../../src/routes/mesh/yarn/+page.server.ts) (same select path as `GET /api/capture/recent`, widened to include completed thoughts; never selects embeddings).
  - **`/mesh/threads`** — the GTD projects the user follows: where it stands, open questions, its thoughts, loose ends. Load: [`mesh/threads/+page.server.ts`](../../src/routes/mesh/threads/+page.server.ts) — reuses the `/memory/projects` prefetch ([`timeline-page-load.ts`](../../src/routes/timeline/timeline-page-load.ts)) and folds it with [`thread-list.ts`](../../src/routes/mesh/threads/thread-list.ts); only promoted GTD projects appear (LLM-judged, never raw entity hubs).
  - **`/mesh/patterns`** — what the mesh notices on its own: one insight sentence plus pattern cards; *Make it a thread* → existing project-create API. Load: [`mesh/patterns/+page.server.ts`](../../src/routes/mesh/patterns/+page.server.ts) streams `getPatternsForUser` ([`server/patterns/`](../../src/lib/server/patterns/)); the LLM judge (JSON-schema contract, no string heuristics) is cached in-process per user per day and also exposed as `GET /api/patterns` ([`api/patterns/+server.ts`](../../src/routes/api/patterns/+server.ts)). A broken judge contract is surfaced as an error, never as fallback copy.
- **`/thought/[id]`** — a thought, up close: a **page, never a modal** — echoes, thread, pattern, edit in place (`/api/capture/edit`), thread assign, and *Forget* with an arm step; ✕ / swipe-down leaves. Load: [`thought/[id]/+page.server.ts`](../../src/routes/thought/[id]/+page.server.ts) (no session → `/login`; missing or forgotten row → 404; reads like `GET /api/thoughts/[thoughtId]`, never the embedding column). Pure helpers colocated under the same directory (echo list, edit request, leave target, pull-to-leave, forget arm).
- **`/chat`** — **Ask.** Raised writer starts below the header ("Ask what you already know" + *Try asking* suggestions: up to 3 newest open thoughts' stored `ask_question`, loaded server-side by [`loadAskSuggestions`](../../src/lib/server/chat/ask-suggestions.ts); none stored → heading only, never raw thought text), portals outside the page mask and docks above bottom navigation once a conversation starts; the thread owns scrolling, wheel/touch motion over the writer forwards to it after textarea bounds, and measured writer height reserves reply clearance; phases *recalling → following the threads → writing* with the mesh spinner; citations open `/thought/[id]`. Agent tool loop over thought CRUD (including `capture_thought`: the agent decides per turn whether the user revealed a durable fact about themselves and stores it as a first-person `as_user` capture; it never stores the question itself) plus chat-only Notes tools (see [ingestion.md](./ingestion.md) Notes section) backed by [`/api/chat`](../../src/routes/api/chat/+server.ts) and session routes; streaming, sessions, credits and voice unchanged.
- **`/feedback`** — **Make me better / Contribute** (header entry, outside the bottom nav). The **shared multiplayer board** ([spec](../planning/feature-multiplayer-board.md)): Requested / In progress / Shipped, search, up/down votes, docked composer. Page loads `GET /api/board` on mount and re-fetches after every write (no `$effect`, no optimistic scores) via [`lib/feedback/board-client.ts`](../../src/lib/feedback/board-client.ts). Share = `POST /api/board/ideas/check` (billed LLM judge: kind, area, duplicate → chorus card "Vote for it instead / Mine's different") then `POST /api/board/ideas` (idea + author's +1 + `feedback` inbox row + email; email failure → `inbox: 'failed'`, idea kept). Votes `PUT /api/board/ideas/:id/vote`; author correct/forget `PATCH`/`DELETE /api/board/ideas/:id` (Requested only); makers (admins) PATCH status/planned/note/hidden. Server: [`lib/server/board/`](../../src/lib/server/board/) (service, judge, share, contract); tables `board_idea` / `board_vote` (migration `0076_board_ideas_votes`) — the first cross-tenant read: ideas readable by any signed-in session, votes owner-only, scores via `board_scores()` SECURITY DEFINER aggregate, maker changes via `board_admin_update()`. MCP: `list_board`, `share_idea`, `vote_idea`, `forget_idea`. `POST /api/feedback` and the client fixture were deleted.
- **`/activity`** — Usage / activity views with the spend chart. Load: [`activity/+page.server.ts`](../../src/routes/activity/+page.server.ts).
- **`/settings`** — User settings (language, theme, LLM provider, **push notifications**; sub-pages `llm`, `agents`, `scheduled-tasks`). Its theme select shares the *Look* contract above with the you-menu. Load: [`settings/+page.server.ts`](../../src/routes/settings/+page.server.ts).
- **`/api-keys`** — API key management UI. Load: [`api-keys/+page.server.ts`](../../src/routes/api-keys/+page.server.ts).
- **`/login`**, **`/register`** — Auth flows (chrome-free).
- **`/eval`** — System evaluation harness (dev only): QA catalog and runs.

### Left out of the chrome on purpose (routed, unlinked)

Decision 1 of the plan: these keep working by URL but have **no nav entry**; the raw graph may return later in some form.

- **`/desk`** — WebGL desk hub (Three.js, imperative factory [`desk/desk-scene.ts`](../../src/routes/desk/desk-scene.ts) + thin Svelte wrapper). Active GTD projects render as piles of paper, open unassigned tasks as loose sheets, graph snapshot nodes as pinned notes; pile click → `/memory/projects/[entityId]`, task click → `/memory/tasks?event=…`. Drag task onto a pile → `POST /api/timeline/projects/assign`; right-click task → `POST /api/temporal-events/[id]/action`. Palette resolves live CSS variables ([`desk/desk-theme.ts`](../../src/routes/desk/desk-theme.ts)) and re-applies on `theme-preference-change`; wall notes carry id/label/kind only — never embeddings. Load: [`desk/+page.server.ts`](../../src/routes/desk/+page.server.ts). Still mounts the legacy `memory-surface-nav`.
- **`/memory/tasks`**, **`/memory/projects`**, **`/memory/projects/[entityId]`**, **`/memory/notes`** — the old Tasks / Projects (with List / Gantt / Kanban and *Tidy up project* review via `POST /api/timeline/projects/[entityId]/review` + `/review/apply`) / Notes pages. Loads: [`memory/tasks/+page.server.ts`](../../src/routes/memory/tasks/+page.server.ts), [`memory/projects/+page.server.ts`](../../src/routes/memory/projects/+page.server.ts) (shared prefetch via [`timeline-page-load.ts`](../../src/routes/timeline/timeline-page-load.ts)), [`project-detail.ts`](../../src/lib/server/memory/project-detail.ts), [`memory/notes/+page.server.ts`](../../src/routes/memory/notes/+page.server.ts). Shared legacy layout: [`memory/+layout.svelte`](../../src/routes/memory/+layout.svelte) + `memory-surface-nav.svelte`. Graph viz components remain under [`src/routes/graph/`](../../src/routes/graph/); tasks/projects UI components under [`src/routes/timeline/`](../../src/routes/timeline/). The old `/memory` graph + embeddings (`?view=embeddings`) hub page is **gone** (see redirects) — it is the one legacy view that is no longer reachable.

### Redirects

- **`/memory` → `/mesh`** (server-side, [`memory/+page.server.ts`](../../src/routes/memory/+page.server.ts)): no session → `/login`; `?thought=<id>` → `/thought/<id>` (the thought deep link the `/graph` chain forwards); every other query param described a retired view and is dropped.
- **Legacy chain (intact):** `/graph` → `/memory` (→ `/mesh`), `/graph?thought=…` → `/memory?thought=…` → `/thought/…`, `/graph?tab=temporal[&event=…]` → `/memory/tasks[?event=…]`; `/timeline[?event=…]` → `/desk[?event=…]`; `/memory/timeline` → `/memory/tasks` (query preserved); `/notes[?note=…]` → `/memory/notes[?note=…]`. Specs: `page.server.spec.ts` beside each redirect.

## API routes (browser or MCP)

- Documented in **ingestion** and **retrieval** domain maps; UI typically hits `/api/capture/*`, `/api/retrieval/search`, `/api/chat/*`, `/api/entities/*`, `/api/thoughts/*`, `/api/patterns`, `/api/board/*` as implemented. When adding a new button, trace to the matching `+server.ts` and update the relevant domain map.
- **PWA / push:** manifest at `static/manifest.webmanifest`; service worker [`src/service-worker.ts`](../../src/service-worker.ts) (push / `notificationclick` + **capture queue Background Sync** — no Workbox precache). Client registration in [`src/routes/+layout.svelte`](../../src/routes/+layout.svelte). Push APIs: `/api/push/subscribe`, `/api/push/unsubscribe`, `/api/push/test`, `/api/push/vapid-public-key` (requires `VAPID_*` env vars).
- **Capture queue (canonical):** [capture-queue.md](./capture-queue.md) — IndexedDB queue, layout runner, service worker Background Sync, queue list UI, ingest step indicator.
