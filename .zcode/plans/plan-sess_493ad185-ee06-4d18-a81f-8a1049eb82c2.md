# Promote Jev to authoritative decision engine (category + content_role), per spec §6 P

## What "Jev as default" can mean — and what it can't (yet)

Jev answers **bounded choices only**. Generation (entity extraction, split-note text, embeddings, relations) physically stays on the chat model — that pipeline is NOT deleted, it becomes the shadow (spec P5: roles reverse).

Per-kind verdict from our 12-capture benchmark + code analysis:

| Kind | Decision | Verdict |
|---|---|---|
| `category` | Jev becomes authoritative | **Promote now** — 12/12 agreement, clean override point at persist |
| `content_role` | Jev decides thought_only vs split | **Promote now** — 12/12 agreement; chat still generates the note text when Jev says split |
| `entity_type` | stays shadow | **Not promotable** — 67% agreement AND Jev only types the dominant mention while the graph sync needs every mention typed (spec O1). Promoting now would corrupt entity resolution. |

Honest caveat for the record: the spec's P-gate asks for ≥95% agreement over ≥100 rows + calibration. You (the operator) approve promotion explicitly at 12 rows — that's P4 satisfied, P1/P2 consciously waived, which the promotion record in the spec doc will state. Rollback = edit one env var. The `measure:jev` benchmark + shadow panel keep accumulating evidence either way.

## New hard dependency (by design, no fallback)

Once a kind is enforced, a Jev failure/timeout/off-catalog answer **fails that enrich attempt loudly** → existing `runIngestWithRetries` ladder (exactly 3) → explicit queue-failure error. Same blast radius as today's LLM-gateway outage. No silent fallback to qwen (guardrail: no fallbacks). Non-enforced kinds (entity_type) keep the never-throw shadow guarantee (AC-S1-4).

## Implementation

**1. Migration** `drizzle/0NNN_decision_shadow_authority.sql` + journal entry (same change, per policy): `ADD COLUMN authoritative_engine text NOT NULL DEFAULT 'chat_judge'`; `ALTER COLUMN llm_choice DROP NOT NULL` (chat answer no longer exists when the split call is skipped). Schema + comments in `brain.schema.ts`.

**2. Config** — `DECISION_ENFORCE_KINDS` (private-env.ts + `resolveDecisionEnforceKinds()` in decision-client.ts): comma-separated subset of `{category, content_role, entity_type}`; absent/empty = off; unknown kind = fail-loud. `.env`: `DECISION_ENFORCE_KINDS=category,content_role`.

**3. decision-plane.ts** (delete-and-replace of the settle contract):
- `startDecisionShadow` → returns `settle(primaries) => Promise<EnforcedDecisions>`; enforced kinds' Jev answers are returned to the caller; enforced-kind failure → settle rejects; non-enforced → error row as today.
- New `startContentRoleDecision({ userId, state })`: early standalone Jev call (content_role needs no catalogs), run **before** the content_split phase. Enforced: awaited (~0.4 s) → mode drives split; failure throws into the retry ladder. Not enforced: not fired.
- Rows for enforced kinds get `authoritative_engine='decision_model'`; the later shadow call carries `content_role` only when NOT enforced (avoids double-asking).
- When content_role is enforced and split runs, the chat's mode is still recorded as `llmChoice`; when the call is skipped, `llmChoice` is null.

**4. enrich-queued-thought.ts**:
- Kick early content_role decision → content_split phase uses Jev's mode. **`thought_only` ⇒ skip the split chat call entirely** (saves ~3 s/capture — the #2 slowest phase; this is the "ditch" made real). `split` ⇒ run generation only.
- At persist: enforced category overrides bundle category — validate Jev's key against active thought_category kinds, resolve `ontologyEntityKindId`, `categoryConfidence` = Jev probability, `categoryAlternatives` = remaining probability map sorted desc (matches existing `{key, confidence}[]` consumer shape), `categorySource: 'decision_model'`. Off-catalog key → throw (same class as today's `InvalidThoughtCategoryError`). Bundle category still recorded in the shadow row.
- Zero added serial latency: content_role settles in parallel with nothing-before-split when enforced+split (~0.4 s) and saves ~2.6 s net on thought_only.

**5. split-capture-content.ts / apply-capture-content-split.ts**: accept `decidedMode` — prompt asks for generation only under the pre-decided mode; `parseSplitFields` validates fields against the decided mode (decided mode always wins over the chat's own `mode`).

**6. Panel/admin** (decision-shadow-query.ts, decision-shadow-panel.svelte, admin endpoint): surface `authoritative_engine` per kind (chip "Jev authoritative" vs "chat judge authoritative"); confusion-pair copy unchanged.

**7. Docs**: spec 09 gains a promotion record per kind (operator approval 2026-10-15, P1/P2 waived at n=12, entity_type deferred on O1); repo-map/ingestion.md decision-plane section updated; benchmark script prints authoritative-engine counts.
